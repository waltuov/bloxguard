# BG002: property sourced module load

Default severity: critical. Confidence is high when the ID and the object that holds it resolve, medium when the target may also hold a value the scanner did not see, and low when the scanner cannot tell which object or value is read.

Severity follows what the scan can see. A finding whose value is stored in the scanned content, in a value object such as an `IntValue` or `StringValue` or in an attribute, is critical. That holds at low confidence too, when the scan cannot fold the stored value into an ID, such as JSON text passed to `JSONDecode` or vector components combined with arithmetic, for a value read through an `ObjectValue` in the file that stores a reference, such as `ptr.Value.Value`, and for a value read from an object the scan cannot pin down, such as `GetChildren()[1].Value`, when the closest known object or anything below it stores an ID shaped value: an integer of at least 1,000,000, or text with a run of at least seven digits, in a value object or an attribute. A low confidence finding where the value cannot be seen is medium, like an unresolved BG001 target: the object cannot be pinned down and nothing near it stores an ID, the content stores no value for it (an attribute set at runtime), or the path leaves the scanned content. It asks for review but does not show that a remote module is loaded: on ordinary code such a `.Value` is often a child named `Value`, such as `require(Package.State.Value)`, or an `ObjectValue` that a loader fills at runtime. The default `fail_on = "high"` does not fail on it.

## What it detects

BG002 reports a numeric module ID that comes from an attribute, value object, or another property in the scanned object tree. A `.Value`, `GetAttribute`, `GetAttributes()` field or loop value read on an object counts, and so does a value derived from such a read, for example through `tonumber`, arithmetic, a type cast, `JSONDecode`, or a string method such as `SoundId:match("%d+")`. Instance `Name` and `ClassName` are read the same way, and a component of an instance value, such as `Vector3Value.Value.X`, keeps its origin.

The object and its origin are kept through local helpers and their parameters, varargs and `select`, `pcall` results, `task.spawn`, `task.defer` and `coroutine.wrap` arguments, a dot call with the receiver first such as `obj.FindFirstChild(obj, "x")`, a method taken as a value such as `local get = obj.GetAttribute; get(obj, "id")`, `table.remove` and `table.unpack` on a list of instances, `QueryDescendants`, `CollectionService:GetTagged`, and the first parameter of a function connected to `ChildAdded`, `DescendantAdded`, or the `Changed` event of a value object.

A property or attribute that any script of the scanned file writes may hold another value at runtime. Writes are found by one pass over every script of the file: `x.P = v`, `x.P += v`, `x["P"] = v` and ``x[`P`] = v``, assignments with several targets, the fields of a table constructor passed to a `Create` call such as `TweenService:Create(o, info, {P = v})`, `TweenService.Create(TweenService, o, info, {P = v})` or `TweenService["Create"](...)`, and `SetAttribute("A", v)` or ``SetAttribute(`A`, v)``. Every name the pass cannot read counts for every property or attribute: a key with an expression, such as `x[name] = v` in a loop over a properties table or ``x[`{a}b`] = v``, a `Create` property argument that is not a table constructor, such as a table in a variable, `Create` or `SetAttribute` taken as a value, `SetAttribute` with a computed name, and `SetAttribute` called with a dot. A read of a written property, `Name` or attribute is the stored value as a candidate next to an unresolved read, so the finding is medium confidence and never says `resolved`. A value the same script writes before the read is listed as a candidate too.

The finding includes the call location and the object or attribute that supplied the value. Low confidence findings come in three kinds. They are medium severity unless the content stores the value:

- The object resolves but its value was not stored, or could not be folded: `module asset ID is read from an instance property or attribute`, with the object and property as origin. An attribute that the content does not store, which would be set at runtime, is reported this way.
- The object is in the scanned content but the scanner cannot pin it down: an element of `GetChildren()` or `GetDescendants()`, such as `GetChildren()[1]` or a loop value, a `FindFirstChildOfClass` or `FindFirstChildWhichIsA` result, a recursive `FindFirstChild(name, true)`, a child picked by a computed name, one of several children with the same name, the object an `ObjectValue` points at, a `ChildAdded` parameter, or a `GetTagged` element when the content has an object with that tag. The message is `module asset ID is read from an object in the scanned content that could not be resolved`, and the related location names the closest known object.
- The path leaves the scanned file or model, or names an object that is not in it, such as an attribute of a player or a `GetTagged` element of a tag the content does not use: `value comes from outside the scanned content`.

```luau
local FAKE_ID = script.Parent.Settings:FindFirstChild("FAKE_ModuleId").Value
require(FAKE_ID)
```

Requiring the instance itself, such as `require(script.Parent:GetChildren()[1])` or `require(ptr.Value)` for an `ObjectValue`, is a local module load and is not reported. This also holds when a loop or a function that runs later stores the instance first, such as `entry.module = script:WaitForChild(entry.name)` followed by `require(entry.module)`. A `.Value` read on such a stored instance is still BG002.

A scan of loose files sees no folders around them, so `script.Parent.Parent.State.Value` leaves the scanned content even when `Value` is a ModuleScript of the same project. Scan the project folder or the built place instead, so these paths resolve.

## Why it matters

Moving an ID out of source makes a remote module load harder to see in code review. The loaded source is still outside the scanned input.

## False positives

Some configuration systems store reviewed module IDs in value objects. Confirm the value, owner, and update process. Treat an unresolved value as a reason for manual review. Module loaders that pass an `ObjectValue` target or a child named `Value` to `require` get the medium, low confidence finding.

## Suppression

Add a suppression for `BG002` that matches the exact path or finding fingerprint. State why the external module is controlled. A trusted ID in `trusted_asset_ids` does not remove a BG002 finding: a value object or attribute is not a constant `require` target, so the finding stays, at medium confidence with the evidence `trusted asset id, not a constant target`.

```toml
[[suppressions]]
rule = "BG002"
path = "/FAKE_System/Loader"
reason = "FAKE test configuration uses a reviewed module ID"
```
