# BG005: obfuscation signals

Default severity: medium. Confidence and severity can rise when a stronger rule also matches.

## What it detects

BG005 reports one finding per script for the first of these signals it sees:

- A long high entropy string literal: at least 256 characters, almost no whitespace, at least 24 different characters and at least 4.5 bits of entropy per character.
- Dense escapes: a string literal with at least 12 numeric escapes, written as `\ddd`, `\xHH` or `\u{...}`, where the escapes make up nearly all of the text. That means at most one byte of other text per escape on average, or at most five source bytes per escape. A `\z` escape and the whitespace it skips are not counted as text.
- A `string.char` call with at least 10 numeric arguments, or at least six `string.byte` calls.
- A VM shaped dispatch loop: a `while`, `repeat` or `for` loop whose body compares one value with at least three different numbers in `if` and `elseif` conditions, in one chain or in nested `if` statements. The value must come from indexed data, such as `ops[pc]`, `inst[1]` or a name assigned from such a read. Conditions in a function declared inside the loop do not count. The script must also have at least 60 tokens, 3 index brackets and 8 numbers.

```luau
local FAKE_TEXT = "\102\097\107\101\102\097\107\101\u{66}\u{61}\u{6b}\u{65}"
local FAKE_VALUE = string.char(70, 65, 75, 69, 95, 86, 65, 76, 85, 69)
```

A loop that calls handlers from a table, such as `handlers[id](...)`, is not a dispatch loop, and neither is a state number that the script sets itself or a comparison with strings.

## Why it matters

Obfuscation can make a loader or data transfer hard to recognize. One signal alone may have a harmless cause, so the finding includes its observed signals.

## False positives

Generated code, compressed data, minified libraries, and serialization tables can resemble obfuscation. Interpreters, emulators and parsers written in Luau that branch on numeric opcodes read from a table have the VM shape by design. Review the source generator and nearby calls.

BG005 reads literals as they are written. It does not fold values, so a payload split into many short strings, rebuilt from a number table, or stored in a `StringValue` is not measured. A dispatch chain in a helper function that a loop calls is not seen as a loop body.

Literal and character-builder findings include a short content hash so replacing data changes the fingerprint. The VM pattern uses literal content across the script because that heuristic does not isolate a VM body. An unrelated literal edit can therefore require a new baseline review. Comments and line positions do not change this hash.

## Suppression

Add a narrow suppression for `BG005`. Explain what generated the source and how it was reviewed.

```toml
[[suppressions]]
rule = "BG005"
path = "/FAKE_Generated/LookupTable"
reason = "FAKE generated lookup table was reviewed at its source"
```
