# BG006: unusual script placement

Default severity: medium. Default confidence depends on the matched signal.

## What it detects

BG006 reports scripts deep inside models or parts, scripts in services that usually hold no code, deceptive names, invisible or look alike characters, and unusual `RunContext` placement.

The file loaders and bundle loader normalize `RunContext` to `Legacy`, `Server`, `Client`, or `Plugin` before this check.

Names are folded before they are compared with core object names such as `Workspace` or `ReplicatedStorage`. Folding removes invisible characters and combining marks, reads fullwidth and mathematical letters as ASCII, drops accents from Latin letters, maps known look alike letters from other scripts, trims surrounding spaces, and treats `0`, `1`, `I`, and `l` as the letters they resemble. A script named `Ｗｏｒｋｓｐａｃｅ`, `Wörkspace`, or `P1ayers` is reported. A name with a character that has no ASCII reading, such as `Café工具`, is not compared.

An example is a server script named `Wоrkspace` where one letter is a Cyrillic look alike character.

## Why it matters

Attackers can place scripts where a normal Explorer review is likely to miss them. Names can also imitate trusted objects.

## False positives

Building tools, imported models, and component systems may place legitimate scripts inside objects. Check the full escaped path, class, enabled state, and run context.

A library that names its modules after core objects gets one medium finding for each, which is expected. On the clean corpus, the Roblox emulator lemur has a module per emulated service, such as `lib/instances/Workspace.lua` and `lib/instances/CoreGui.lua`, and gets nine. Review them once and suppress the folder by path.

## Suppression

Add a suppression for `BG006` at the exact object path. State the design reason for the placement or name.

```toml
[[suppressions]]
rule = "BG006"
path = "/FAKE_BuildTool/Part/Controller"
reason = "FAKE component stores its controller beside the part"
```
