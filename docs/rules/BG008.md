# BG008: HTTP exfiltration

Default severity: high. Confidence depends on the endpoint and data flow. Some cases are medium, listed below.

## What it detects

BG008 reports HTTP requests to webhook or paste style endpoints. URLs are percent decoded and repeated `/`, `.`, and `..` path segments are collapsed before matching. A path containing `/api/webhooks/` or a versioned form such as `/api/v10/webhooks/` is treated as a webhook on any host, and so is a Discord `/api/` path. Discord invite links are not.

A call of `GetAsync`, `PostAsync`, `PostAsyncFullUrl` or `RequestAsync` is an HTTP request when its receiver is `HttpService`, in any lookup form (`GetService`, `FindService`, `service`, `game.HttpService`) or alias, also when it is a helper's parameter, a `pcall` result, or looked up through a method value such as `local get = game.GetService; get(game, "HttpService")`, or when the receiver is unknown and the request names a URL. A receiver known to be another object never counts: DataStore, OrderedDataStore and MemoryStore objects share these method names, and their calls are not reported, also when the store is reached the same ways.

The rule also reports outbound requests that include player or game data: `UserId`, player names and `DisplayName`, `PlaceId`, `GameId`, `JobId`, `PrivateServerId`, `PrivateServerOwnerId`, `game.CreatorId`, and `AccountAge`. Sensitive values remain tracked when they pass through local variables, table fields, `table.create`, `table.move`, an encoded request body, headers, URL prefixes, string formatting, the result of a `gsub` callback, helper functions, and strings built in a loop such as `body = body .. p.Name`. A sender function that reads a body assigned after the function was defined is checked where it is called. The elements of `Players:GetPlayers()` and the first parameter of a function connected to `PlayerAdded` or `PlayerRemoving` are players, whatever the variable is called. Calls through aliases such as `H.RequestAsync(H, ...)` or `pcall(H.PostAsync, H, ...)` are traced too, and so is a wrapper such as a method named `GetAsync` that sends the request, reported at the call.

These cases are medium severity:

- a request to a raw IP address,
- a webhook URL constant anywhere in a script, even when the call that uses it cannot be traced,
- an HTTP GET request that carries player or game data in its URL, because games often send such requests to their own backend.

```luau
local FAKE_URL = "https://discord.com/api/webhooks/000/FAKE"
HttpService:PostAsync(FAKE_URL, "FAKE")
```

## Why it matters

Outbound requests can disclose player, game, server, or developer data. Webhook endpoints often bypass a service that the project owner controls.

## False positives

Legitimate analytics and error reporting send data outside the experience. Review the endpoint owner, fields, consent, retention, and failure behavior. Two shapes are known false positives because the rule treats these identifiers as sensitive:

- Analytics that sends `player.UserId`. For example, a `PlayerAdded` handler that posts `HttpService:JSONEncode({user = player.UserId})` to a fixed analytics endpoint is reported at high severity. The evaluation suite keeps a synthetic case of that shape as a documented false positive.
- A server browser or matchmaking heartbeat that posts `game.JobId` and `game.PlaceId` to the game's own backend is reported at high severity too.

## Suppression

Add a suppression for `BG008` at the reviewed analytics client. State who controls the endpoint and what data leaves the game.

```toml
[[suppressions]]
rule = "BG008"
path = "/FAKE_Analytics/Reporter"
reason = "FAKE analytics endpoint receives only aggregate test counters"
```
