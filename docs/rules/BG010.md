# BG010: prompts and redirects

Default severity: medium. Default confidence: medium.

## What it detects

BG010 reports purchase prompts and teleports started by inserted content.

The prompts are `PromptPurchase`, `PromptProductPurchase`, `PromptGamePassPurchase`, `PromptBundlePurchase`, `PromptPremiumPurchase` and `PromptSubscriptionPurchase`. The teleports are `Teleport`, `TeleportAsync`, `TeleportToPlaceInstance`, `TeleportToPrivateServer` and `TeleportPartyAsync` with a numeric place ID. A teleport whose player list is a known empty table moves no one and is not reported. Method values and dot calls such as `TS.TeleportPartyAsync(TS, ...)` count too.

Inserted content means a script inside a `Model`, `Tool`, `Part`, `MeshPart` or `Accessory` of the scanned file, which is how free models and inserted kits arrive. This condition is by design: a place's own shop or portal script in `ServerScriptService`, a plain source file, and source scanned through MCP `scan_source` have no such ancestor, so the same call there gives no BG010 finding.

For example, a model file `FAKE_Kit.rbxm` holds a `Model` named `FAKE_Kit` with a `Script` inside it. This script source gets a BG010 finding:

```luau
local FAKE_PLACE_ID = 999000000000010
local TeleportService = game:GetService("TeleportService")
game:GetService("Players").PlayerAdded:Connect(function(player)
    TeleportService:Teleport(FAKE_PLACE_ID, player)
end)
```

## Why it matters

Inserted content can pressure players into a purchase or redirect them away from the intended experience.

## False positives

Real shops, portals, and game hubs use these APIs. Confirm the product or destination belongs to the project and that the prompt is expected.

## Suppression

Add a suppression for `BG010` at the reviewed shop or portal. State which destination or purchase flow is approved.

```toml
[[suppressions]]
rule = "BG010"
path = "/FAKE_Hub/Portal"
reason = "FAKE portal target is part of this test universe"
```
